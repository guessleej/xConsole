# xConsole　OWASP ASVS 5.0 Level 2 檢核表

> 版本：v1.0　日期：2026/10/22　等級依 `docs/SECURITY_PLAN.md`：中級 → ASVS L2
> 每條三選一：符合（證據）／不適用（理由）／待補（期限）。測試編號指 `手冊/資安證據/掃描報告/` 內的輸出。

## V1 編碼與架構

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 1.1 | 有威脅模型且隨重大變更更新 | 符合 | `docs/THREAT_MODEL.md`（2026/10/25 補上加入機器、機器設定、情境、編譯、指令注入與被接管代理等條目） |
| 1.2 | 元件與依賴清單（SBOM） | 符合 | `sbom-source.cdx.json`、`sbom-runtime.cdx.json` |
| 1.3 | 安全控制集中實作 | 符合 | 遮罩 `store.redact()`、加密 `tls.seal()`、錯誤處理 `handle_one_request`、登入閘門 `_need_auth()` |
| 1.4 | 不信任用戶端送來的身分 | 符合 | 身分只由伺服器端票證查出；請求內容沒有任何身分欄位被採信 |

## V2 驗證與 V5 輸入處理

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 2.1 | 伺服端正向驗證 | 符合 | 路徑參數 `[\w.-]+`；API 設定逐欄驗證（模型名稱、網址、上下文、輸出上限）；整合測試「模型名稱有空白或分號 → 400」 |
| 2.2 | JSON 欄位型別與長度 | 符合 | 帳號截 64 字、票證超過 200 字直接拒絕、網址 200 字上限、請求 6 MB 上限 |
| 2.3 | 禁 mass assignment | 符合 | 機器設定、欄位、情境都只收白名單欄位，記錄檔與設定檔路徑、其他引擎參數一律忽略（機器管理整合測試「改不到記錄檔」「情境裡塞其他參數會被忽略」）；API 設定只取 `public_url、model_name、max_context、max_tokens、key` 五個欄位轉給代理 |
| 5.1 | 參數化查詢 | 符合 | SQLite 全部 `?` 佔位符 |
| 5.2 | 作業系統命令不接使用者輸入 | 符合 | 一律以參數清單執行、不經 shell，服務名稱比對格式並加 `--`；代理單元測試「sh() 收字串要拒絕」「原始碼沒有 shell=True」 |
| 5.3 | 路徑穿越防護 | 符合 | 安全測試「靜態檔路徑穿越」「讀記錄不能穿越」「換模型不能指到任意路徑」 |
| 5.4 | SSRF 防護 | 符合 | 機器 id 只在名單內查（安全測試「拿 IP 當機器 id → 404」）；經網路實測只打管理者設定的網址且不跟轉址（整合測試） |

## V3 Web 前端

## V6 認證

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 6.1 | 自管密碼的雜湊與長度 | 符合 | PBKDF2-SHA256 200,000 輪加鹽；最少 8 碼（ASVS 建議 12 碼，交付時建議客戶設 12 碼以上，見待補） |
| 6.2 | 登入失敗節流 | 符合 | 安全測試「同一來源連錯 5 次後回 429」「被擋期間連正確密碼也不放行」；機器管理整合測試「同時送 20 次錯的密碼，最多 5 次被驗」；不做全域封鎖，避免任何人都能把管理者鎖在門外 |
| 6.3 | MFA | 待補 | THREAT_MODEL 缺口 G3，2027/03/31 |
| 6.4 | OAuth／OIDC | 不適用 | 不串接外部身分提供者 |
| 6.5 | 失敗訊息不區分帳號存在與否 | 符合 | 一律「帳號或密碼不對」 |
| 6.6 | 服務對服務認證 | 符合 | 主控台對代理：各機一把 256 位元權杖＋憑證釘選；重新部署即更換 |

## V7 會話管理

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 7.1 | 會話有效期 | 符合 | 12 小時（單一管理者的維運工具，以伺服器端票證可即時撤銷補足） |
| 7.2 | 登出使票證失效 | 符合 | 安全測試「登出後同一張票證在伺服器端作廢」「同一條連線上登出後 401」 |
| 7.3 | 權限變更即時生效 | 符合 | 安全測試「換密碼後所有既有登入一起作廢」 |
| 7.4 | token 不進 localStorage | 符合 | 票證只在 HttpOnly cookie |

## V8 授權

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 8.1 | 每個端點伺服端驗權、預設拒絕 | 符合 | 安全測試「未登入打 23 支 API 全部回 401」；不需登入的只有登入、登出、加入機器，加入要帶一次性加入碼（機器管理整合測試第 1 節） |
| 8.2 | 物件層授權（IDOR） | 符合 | 單一租戶系統，物件為機器與欄位：只能指到登錄檔內的項目（安全測試第 4 節） |
| 8.3 | 功能層授權 | 不適用 | 只有管理者一種角色 |
| 8.4 | 前端隱藏不等於授權 | 符合 | 安全測試直接以 HTTP 繞過前端 |
| 8.5 | 租戶識別只來自 token | 不適用 | 無租戶 |

## V12 安全通訊

| 條 | 要求 | 結果 | 證據 |
|---|---|---|---|
| 12.1 | 全站 TLS、HSTS | 符合（主控台與代理）／待補（模型 API） | 安全測試「TLS 1.1 以下連不上」「http 一律 308」；`check-https.sh` 缺 0；模型 API 為 http，缺口 G1，2026/12/31 |
| 12.2 | 對外呼叫驗證憑證 | 符合 | 主控台對代理以釘選憑證驗證，加入時只收剛好一張非 CA 憑證；安裝指令以 `curl --pinnedpubkey` 釘主控台公鑰（測試驗過錯的公鑰連不上）；經網路實測遇到 https 用系統 CA 並驗主機名稱 |
