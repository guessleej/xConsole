# xConsole　滲透測試自測報告

> 日期：2026/10/22　執行者：李偉業（云碩科技）　性質：開發團隊自測，非第三方測試（第三方測試列於 THREAT_MODEL 缺口 G4）

## 範圍與方法

測試對象是 xConsole 主控台（`console/xconsole_server.py`）與節點代理（`agent/xconsole_agent.py`）。測試全部在 .27 上以隔離實例進行：獨立的使用者目錄、隨機埠、測試帳密，模型服務以假引擎（`test/fixtures/mock_llm.py`）掛成臨時 systemd 服務代替，不碰正式環境的資料與模型。

我們從攻擊者的角度寫成可重跑的測試，兩支合計 75 項，每次 PR 都在 CI 重跑：

| 測試 | 項數 | 涵蓋 | 原始輸出 |
|---|---|---|---|
| `test/security/test_security.py` | 52 | 未登入存取、票證竄改／自編／過期／登出／keep-alive、CSRF（415）、超大與畸形請求、IDOR 等價（機器與欄位 id）、SSRF、路徑穿越、換密碼、安全標頭、http 降級、舊版 TLS、登入節流、稽核與設定檔不留機密、代理權杖與路徑注入 | `掃描報告/安全測試-test_security.txt` |
| `test/test_api_integration.py` | 23 | API 串接設定的輸入驗證、金鑰只回傳一次且不進稽核、設定檔權限、套用失敗自動還原、經網路實測不跟轉址 | `掃描報告/API串接整合測試.txt` |

另以 CI 的 OWASP ZAP baseline 對執行中的主控台做被動掃描，以 gitleaks、pip-audit、grype、trivy 做靜態與供應鏈掃描，結果在 `掃描報告/`。

## 發現與處置

| # | 發現 | 嚴重度 | 處置 | 狀態 |
|---|---|---|---|---|
| F1 | 同一條 keep-alive 連線上，上一個請求查到的身分會被下一個請求沿用：登出後在同一條連線上仍是登入狀態；反過來，登入後的第一個請求會被當成未登入 | 高 | 每個請求開始時清掉身分快取；新增測試「同一條連線上：登入前 401 → 登入後 200 → 登出後 401」，修正前確認此測試會失敗 | 已修正 |
| F2 | 請求宣稱的 Content-Length 超過上限時，伺服器仍照宣稱長度讀 6 MB；負數長度會讓讀取卡到連線結束，執行緒被占住 | 中 | 超過上限立即 413 並關閉連線；負數視為 0 | 已修正 |
| F3 | 主控台端的代理權杖以明文存在 `fleet.json`（僅靠 0600 權限） | 中 | 改為 AES-256-GCM 加密落地，啟動時自動遷移既有明文；正式環境 3 把權杖已轉為密文 | 已修正 |
| F4 | 開啟模型 API 金鑰後，健康檢查把 401 當成服務沒起來，會誤觸發自動還原 | 中（可用性） | 健康檢查把 401 視為服務存活 | 已修正 |
| F5 | 經網路實測會跟隨轉址，若對外網址被設成會轉址的位址，金鑰會被帶到別處 | 中 | 實測改為不跟轉址並回報原因 | 已修正 |
| F6 | 舊版無狀態簽章票證：登出只清瀏覽器 cookie，被取走的票證 12 小時內仍可用 | 中 | 改為伺服器端票證，資料庫只存雜湊 | 已修正 |
| F7 | 模型 API 走 http，金鑰與提示在內網明文傳輸 | 中 | 畫面明示；THREAT_MODEL 缺口 G1 | 未修正，期限 2026/12/31 |
| F8 | 管理者登入沒有 MFA | 中 | 節流與換密碼作廢補強；缺口 G3 | 未修正，期限 2027/03/31 |

## 結論

本次自測修正 6 項，2 項列入缺口清單並訂有期限。修正後兩支測試 75 項全數通過，靜態與供應鏈掃描皆為 0 項弱點。這份報告不能取代第三方滲透測試；交付中級以上的政府案前，依合約安排第三方測試。
