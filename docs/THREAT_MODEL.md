# xConsole 模型主控台威脅模型（STRIDE）

> 版本：v1.1　日期：2026/11/06　依據：SECURITY_PLAN v1.1 第 4 節邊界清單
> 每條跨邊界的資料流至少分析一次 STRIDE；每個威脅對應一個控制措施與 ASVS 條號；沒有控制措施的列進第 6 節缺口清單。
> 「狀態」欄的「已測」代表 `test/security/test_security.py` 或 `test/test_api_integration.py` 有對應的測試項；
> 第 3b～3d 節（2026/11 新增）的「已測」對應 `agent/test_agent_mode.py`、`console/test_agent_tasks.py`、`console/test_providers.py`、`console/test_preview.py`、`console/test_e2e_features.py`。

## 圖例

S 假冒（Spoofing）／T 竄改（Tampering）／R 否認（Repudiation）／I 資訊洩漏（Information Disclosure）／D 阻斷（Denial of Service）／E 權限提升（Elevation of Privilege）

## 2. B2 主控台 ↔ 節點代理（物件層授權，等同多租戶系統的 IDOR／跨租戶檢查）

本系統沒有租戶，但「拿一個 id 去操作不屬於你的東西」這類 IDOR 問題一樣存在：機器 id 與欄位 id 都來自網址。這一節對應多租戶系統的跨租戶隔離檢查。

| 威脅 | 類型 | 情境 | 控制措施 | ASVS | 狀態 |
|---|---|---|---|---|---|
| 拿 id 指到不在名單內的主機（SSRF 跳板） | E | `/api/node/127.0.0.1/state`、`/api/node/任意/…` | 機器 id 只在 `fleet.json` 名單內查，查不到回 404；主機位址只來自名單，不來自請求 | V8.2、V5.4 | 已測 |
| 假冒節點代理 | S | 有人在同 IP 架假代理騙主控台 | 主控台以部署時經 SSH 取回的各機憑證驗證對方；沒有該機憑證就不連，不退回不驗證或 http | V12.2 | 已測 |
| 偷到代理權杖直接打代理 | E | 權杖外洩 | 權杖只走 Authorization 標頭，網址帶權杖一律 401；主控台端加密落地；畫面與 API 永不回傳權杖 | V11.2 | 已測 |
| 透過換模型指到任意檔案 | E／I | `pack=../../etc`、`native=/etc/passwd` | 只接受本機掃描清單內的模型組合 | V5.3 | 已測 |
| 透過改登錄檔讀出私鑰 | I | 把欄位記錄檔指到 `~/.ssh/id_rsa` 再讀 `/logs` | 代理不開放整份覆寫登錄檔；網頁上的機器設定與欄位管理只收白名單欄位，記錄檔與設定檔路徑不能從網頁改（`test_machine_admin.py` 送 `log`、`config` 會被忽略） | V8.2 | 已測 |
| 把存放區或 llama-server 指到危險位置 | E／I | 存放區設成 `/etc`、`~/.ssh`、家目錄；llama-server 指到 `/bin/sh` | 存放區不准系統目錄、隱藏資料夾、家目錄本身，要寫得進去；llama-server 檔名必須是 `llama-server` 且 `--version` 跑得起來 | V5.3、V8.2 | 已測 |
| 命令注入 | E | 欄位 id、服務名稱帶 shell 字元 | 路徑參數 `[\w.-]+` 白名單；所有命令參數 `shlex.quote` | V5.2 | CodeQL |
| 改設定把機器記憶體吃爆 | D | 把上下文調到極大 | 調大前做記憶體准入試算，不夠就擋（要強制得二次確認）；套用後打不通自動換回 | V13 | 已測 |
| 被接管的代理拖垮主控台 | D | 代理回幾 GB 的內容，或每 29 秒吐一個位元組 | 讀代理回應有 32 MB 上限與總時限（等待時限＋60 秒） | V13 | 已測 |
| 經情境寫任意引擎參數 | E／T | 在情境裡塞帶檔案路徑的參數 | 網頁上只開放上下文長度、並行數、自動縮輸出上限三項，其他參數一律忽略 | V5.1、V8.2 | 已測 |
| 經「編譯 llama.cpp」執行別的程式 | E | 改原始碼來源或編譯參數 | 來源固定為 llama.cpp 官方 repo、版本固定為最新正式版編號；編譯參數由代理依硬體決定，網頁不能傳入；只編在家目錄底下 | V10、V14 | 已測 |
| 執行外部指令時被注入 | E | 服務名稱、路徑帶 shell 字元或以 `-` 開頭 | 一律用參數清單、不經過 shell；服務名稱比對格式並在參數前加 `--`；原始碼不准出現 `shell=True` | V5.2 | 已測 |

## 2b. B7 新機器 ↔ 主控台（加一台機器：不需登入的兩個端點）

管理者在網頁產生加入碼與安裝指令，新機器執行指令時會打兩個不需登入的端點：`GET /install/<加入碼>/…`（下載安裝腳本與代理程式）與 `POST /api/join`（送回代理的權杖與憑證）。

| 威脅 | 類型 | 情境 | 控制措施 | ASVS | 狀態 |
|---|---|---|---|---|---|
| 沒有加入碼的人把自己的機器加進來 | S／E | 內網有人直接打 `/api/join` | 加入碼 144 位元隨機、只存雜湊、30 分鐘、只能用一次；產碼要登入；同一來源失敗 10 次擋 15 分鐘 | V6.3、V11 | 已測 |
| 中間人換掉安裝腳本或代理程式 | T | 新機器下載時被攔截 | 安裝指令釘住主控台憑證的公鑰（`curl --pinnedpubkey`），公鑰不對就連不上；不是 `-k` 關掉驗證 | V12.2 | 已測 |
| 送來假的代理資訊 | S | 送一個連不到、或權杖不對的代理 | 主控台用送來的憑證與權杖實際連一次（含主機名稱驗證），連得上才納管；失敗原因顯示給管理者，但不含連線細節（不能拿來分辨埠的狀態） | V12.2 | 已測 |
| 搶走已納管的機器 | S／E | 持碼者送「別台代理的憑證＋自己的 CA」整串，讓主控台以為是同一台重新加入，改連到攻擊者 | 加入時只收剛好一張、不是 CA 的憑證；同一台的判斷靠這張憑證，而連線驗證要握得出這張憑證的私鑰（2026/10/25 審查重現後修正） | V12.2、V8 | 已測 |
| 加入碼被卡死 | D | 送畸形內容讓加入流程中途出錯 | 驗證期間鎖住的加入碼，不論怎麼結束都會放回 | V11 | 已測 |
| 加入碼外洩後被搶用 | S | 指令被別人先拿去執行 | 只能用一次，用過網頁上就顯示「已加入」並可立刻移除；30 分鐘到期 | V11 | 已測 |
| 權杖外洩 | I | 加入時送來的權杖被記下 | 只走 TLS（釘公鑰）的請求本文；收到後加密落地；不寫進操作紀錄與回應 | V11.2、V16.3 | 已測 |
| 加入碼出現在網址 | I | 網址留在記錄 | 主控台不寫存取記錄；加入碼只能用一次、30 分鐘到期，屬一次性票證 | V7 | 符合 |
| 未授權改名、換位址或移除機器 | E | 未登入或冒用 | 都要登入；換位址先實際連一次，連不上自動改回；每個動作寫稽核 | V8、V16 | 已測 |

## 3b. B8 Agent ↔ 這台機器（模型規劃、代理實際寫檔與執行指令）

Agent 模式讓模型（本機欄位或第三方 API）透過六個工具在一台機器上做事：列檔、讀檔、寫檔、執行指令、更新計畫、完成。
對話迴圈在主控台的背景執行緒；檔案與指令由那台機器的代理實際做（`/agent/*`）。模型的輸出在這裡**會被執行**，所以是全系統風險最高的邊界。

| 威脅 | 類型 | 情境 | 控制措施 | ASVS／AI | 狀態 |
|---|---|---|---|---|---|
| 沒打算給 Agent 用的機器被拿來執行指令 | E | 偷到代理權杖或主控台登入後直接打 `/agent/exec` | 每台預設關閉（`machine.agent_enabled`），只能由管理者在「這台的設定」打開並寫稽核；關閉時 `/agent/*` 一律 403 | V8.1 | 已測 |
| 模型被提示注入，執行破壞性指令 | E／T | 讀到的檔案或網頁內容夾帶「刪掉家目錄」之類的指示 | `run_command` 一律先停在 `waiting_approval`，畫面顯示完整指令，人按允許才送出；拒絕時把「使用者拒絕」當工具結果回給模型；「之後不再問」只對這一個任務有效 | AI-1 | 已測 |
| 寫檔、讀檔跳出工作資料夾 | E／I | `../../.ssh/id_rsa`、絕對路徑、Windows 磁碟代號、資料夾內放指向外面的符號連結 | 路徑不准絕對路徑與 `..`；組完路徑 realpath 後必須還在 `~/xconsole-agent/<資料夾>/` 底下（符號連結解開後再比）；寫檔前上層資料夾再驗一次、開檔加 `O_NOFOLLOW`；工作資料夾本身只能是根目錄第一層、不是指出去的連結 | V5.3、V12.3 | 已測 |
| 指令讀到代理權杖或其他金鑰 | I | `env`、`printenv` 把環境變數印給模型 | 指令的環境變數拿掉代理權杖本身與任何名稱以 `KEY`／`TOKEN`／`SECRET`／`PASSWORD`／`CREDENTIAL` 結尾或 `XCONSOLE_` 開頭的；代理權杖本來就只存檔案、不在環境變數 | V11.2、V14.3 | 已測 |
| 指令本身擋不住（可以 cd 出去） | E | 允許之後的指令以代理帳號的權限執行 | 明確告知使用者：路徑限制只管檔案工具，指令的權限等同代理帳號；所以每條都要核准、工作目錄固定在該資料夾、記稽核。建議交付時代理用一般帳號（安裝程式本來就拒絕 root） | AI-1 | 符合 |
| 指令跑不停或狂吐輸出拖垮代理 | D | `yes`、無窮迴圈、一次輸出幾 GB | 逾時預設 120 秒、上限 600 秒，到時收掉整個行程群組；標準輸出與錯誤各只留 32 KB（頭尾保留、中間丟掉，記憶體用量固定）；在 systemd 底下另開 scope，不跟代理搶 256 MB 上限 | V13 | 已測 |
| 任務失控 | D | 模型一直呼叫工具 | 每個任務最多 40 步、30 分鐘；同時只能有一個進行中的任務；隨時可按停止 | AI-5 | 已測 |
| 否認執行過某條指令 | R | 出事後說不是自己按的 | 每條實際執行的指令寫稽核（帳號、來源 IP、機器／資料夾、指令前 300 字經遮罩、結束碼、是否逾時），核准與拒絕也各記一筆 | V16.1 | 已測 |
| 模型不支援工具呼叫，任務卡住或亂回 | D | 推理引擎沒開 `--jinja`、模型沒有工具範本 | 第一步就被拒收 tools，或連續兩輪都不呼叫工具，任務直接以「不支援工具呼叫，請換模型」結束 | — | 已測 |

## 3c. B9 主控台 ↔ 第三方 API（OpenAI 相容服務與它們的金鑰）

管理者可以在「設定 → 第三方 API」加 OpenAI、Gemini、Anthropic、Mistral 或自訂的 OpenAI 相容服務；對話與 Agent 都可以選用。
這是 xConsole 第一個會把使用者內容送出機器之外的功能。

| 威脅 | 類型 | 情境 | 控制措施 | ASVS／AI | 狀態 |
|---|---|---|---|---|---|
| 金鑰從資料庫外洩 | I | 資料庫檔或備份被拷走 | 金鑰 AES-256-GCM 加密（`enc:v1:`，主金鑰 `master.key` 0600）後才寫進 SQLite；儲存層拒收沒加密的值；測試確認資料庫檔（含 WAL）找不到明文 | V11.1、V14.2 | 已測 |
| 金鑰從畫面或 API 外洩 | I | 前端或任何 GET 回傳金鑰 | `GET /api/providers` 只回 `key_set`；編輯時金鑰欄空白＝保留原金鑰，前端永遠拿不到舊值 | V14.2 | 已測 |
| 金鑰流進記錄、稽核、錯誤回應 | I | 對方服務把收到的金鑰寫在錯誤訊息裡 | 錯誤訊息回給畫面前把這把金鑰與常見金鑰格式（`sk-`、`AIza`、`Bearer …`）遮掉；稽核只記「換新／保留／清除」 | V16.3 | 已測 |
| 金鑰被帶到別的主機 | I | 對方回轉址、或網址被改成攻擊者的主機 | 不跟轉址；金鑰只走 `Authorization` 標頭（不進網址，網址帶查詢字串直接拒收）；只有登入的管理者能改網址並寫稽核 | V5.4、V14.3 | 已測 |
| 經第三方 API 設定打內網（SSRF） | E | 網址填 `http://169.254.169.254/` 或內網服務 | 只收 https；http 只准私有位址與本機，且不准 169.254（雲端 metadata）；連線前解析並確認，直接連檢查過的那個 IP（防 DNS 在檢查與連線之間換位址） | V5.4、V12.3 | 已測 |
| 中間人假冒服務 | S | 內網有人攔截 https | 一律驗證憑證、TLS 1.2 以上；自建 CA 的服務在該筆設定匯入對方的 CA 憑證，不提供關閉驗證 | V12.2 | 已測 |
| 政府案用到中國來源服務 | — | 管理者自己填了中國廠商的網址 | 預設清單不內建任何中國廠商；主機名稱或模型名稱屬中國來源的一律標 `cn_origin`，畫面提醒 | AI-3 | 已測 |
| 資料出境 | I | 對話與 Agent 的檔案內容送到外部供應商 | 只有管理者明確新增並選用第三方 API 時才會送出；對話與 Agent 畫面標示「外部」；本機模型的路徑不變 | AI-2 | 符合 |

## 3d. B10 瀏覽器 ↔ 執行預覽（模型寫出的 HTML 在主控台網域上執行）

## 4. B5 AI 與模型（有 LLM 的系統必寫）

xConsole 原本只管模型服務的啟停與設定。2026/11 起多了三個會用到模型輸出的功能：網頁對話、執行預覽與 Agent，
其中 Agent 會依模型輸出寫檔與執行指令（見 3b），執行預覽會執行模型寫出的 HTML（見 3d），第三方 API 會把內容送出機器（見 3c）。

| 威脅 | 類型 | 情境 | 控制措施 | ASVS／AI | 狀態 |
|---|---|---|---|---|---|
| 提示注入 | T／E | 模型輸出被拿去執行 | API 實測只送固定提示、回答只顯示；Agent 的指令每一條都要人核准、檔案工具限在工作資料夾（3b）；執行預覽關在 sandbox（3d） | AI-1 | 已測 |
| 資料出境 | I | 內容送到外部模型供應商 | 預設不呼叫任何外部服務；只有管理者新增並選用第三方 API 時才會送出（3c） | AI-2 | 符合 |
| 模型來源不合規 | — | 政府案用了中國來源模型或服務 | 推薦清單不收中國來源；Hugging Face 與已安裝清單標 `cn_origin`；第三方 API 預設清單不內建中國廠商、自訂填的也會標 | AI-3 | 符合 |
| 換模型無法追溯 | R | 誰在什麼時候把哪台換成哪顆 | 換模型、改 API 設定、實測都寫稽核 | AI-4、V16 | 已測 |
| 用量耗盡 | D | 有人迴圈呼叫模型 | 屬模型引擎的職責（並行數、單次輸出上限可在網頁上設）；主控台提供金鑰限制誰能用 | AI-5 | 部分 |

## 5之二. 認證回跳（OAuth／OIDC callback）

不適用：xConsole 不串接任何外部身分提供者，沒有 OAuth／OIDC 授權碼流程，也沒有認證回跳網址可被竄改或開放轉址。日後若要接客戶的 Entra ID 或校務單一登入，必須先補這一節（PKCE、state、redirect_uri 嚴格比對）再上線。
