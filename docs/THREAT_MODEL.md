# xConsole模型主控台威脅模型（STRIDE）

> 版本：v2.4　日期：2026/11/25　依據：SECURITY_PLAN v1.2第4節邊界清單
> 每條跨邊界的資料流至少分析一次STRIDE；每個威脅對應一個控制措施與ASVS條號；沒有控制措施的列進第6節缺口清單。
> 「狀態」欄的「已測」代表 `test/security/test_security.py` 或 `test/test_api_integration.py` 有對應的測試項；
> 第3b～3d節（2026/11新增）的「已測」對應 `agent/test_agent_mode.py`、`console/test_agent_tasks.py`、`console/test_providers.py`、`console/test_preview.py`、`console/test_e2e_features.py`。

## 圖例

工作站規劃（`docs/WORKSTATION_FLEET.md`第六節）另有一套B5～B9編號，跟本文件的編號對照如下：B5代理 → 主控台通道＝本文件B13（2c節）；B6工作站互傳＝B14（2d節）；B7模組載入＝B12（3f節）；B8群組加入＝B7（2b節）；B9本機使用者 → 系統代理＝B15（2e節）。

S假冒（Spoofing）／T竄改（Tampering）／R否認（Repudiation）／I資訊洩漏（Information Disclosure）／D阻斷（Denial of Service）／E權限提升（Elevation of Privilege）

## 3b. B8 Agent ↔ 這台機器（模型規劃、代理實際寫檔與執行指令）

對話迴圈在主控台的背景執行緒；檔案與指令由那台機器的代理實際做（`/agent/*`）。模型的輸出在這裡**會被執行**，所以是全系統風險最高的邊界。

## 4. B5 AI與模型（有LLM的系統必寫）

其中Agent會依模型輸出寫檔與執行指令（見3b），執行預覽會執行模型寫出的HTML（見3d），第三方API會把內容送出機器（見3c）。

## 5之二. 認證回跳（OAuth／OIDC callback）

不適用：xConsole不串接任何外部身分提供者，沒有OAuth／OIDC授權碼流程，也沒有認證回跳網址可被竄改或開放轉址。日後若要接客戶的Entra ID或校務單一登入，必須先補這一節（PKCE、state、redirect_uri嚴格比對）再上線。
