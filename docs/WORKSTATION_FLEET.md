# 多工作站管理規劃（核心）

2026-11-07 定案範圍。本檔是公開核心這一側的真本：每一項做完把狀態改成「完成」並寫上 PR。
企業版模組（閉源）的規劃在私有 repo `xConsole-Enterprise` 的 `docs/PLAN.md`，本檔只寫核心要提供的機制與兩邊的介面合約。

## 版本名稱

| 版本 | 名稱 | 說明 |
|---|---|---|
| 個人版 | xConsole Personal | 桌面安裝檔、管一台。它是開源核心的一種使用方式，不另開 repo |
| 企業版 | xConsole Enterprise | 閉源模組，內含教育包與企業包，放在私有 repo `xConsole-Enterprise` |

開源 repo 維持 `guessleej/xConsole` 不改名：線上更新（`console/updater.py` 的 `REPO`）寫死問這個位置，已安裝的個人版都靠它更新。

## 一、要解決的情境

| 情境 | 規模 | 機型 | 誰在管 | 誰在用 |
|---|---|---|---|---|
| 個人（xConsole Personal） | 1 台 | 任何電腦 | 自己 | 自己 |
| 學校電腦教室 | 一間 20 台，全校數間 | 5090 桌機、AI 395、MIC-743、DGX GB10 混搭 | 老師管自己那間，資訊組看全校 | 學生，多人輪流用同一台 |
| 企業 | 數十到數百台 | 同上，另有 AI 395 筆電；MIC-743 多在產線 | IT 管全公司，部門主管看自己部門 | 員工，多半一人一台 |

個人版（xConsole Personal）維持現狀，本規劃不動它。學校與企業情境要搭配企業版（xConsole Enterprise）。機器只有「加入群組」之後才受管，退出群組就回到個人版。

這些機器是**工作站，不是伺服器**。規劃全部以這幾件事為前提：

- 每天開關機，筆電會休眠、會被帶回家。
- IP 由 DHCP 配，會變。
- Windows 防火牆、公用網路設定擋住連進來的連線（HP 實測過：公用網路下別台連不到 9400）。
- 學校常裝還原卡，重開機就還原系統碟；派送時多半用同一份映像複製。
- 前面坐著人，瀏覽器、Office、IDE 都在吃記憶體。

現在的設計是主控台連到固定位址的代理，當場下指令。這套適合機房，搬到工作站上會一路卡住。

## 二、角色與動線

照實際使用的順序排，最常做的放最前面。

**老師／IT（管理者）**

| 步驟 | 做什麼 | 前一步 | 做完去哪 |
|---|---|---|---|
| 1. 建群組 | 在主控台建「三樓電腦教室」或「研發部」 | 主控台已安裝並登入 | 產生群組加入碼 |
| 2. 加入機器 | 把加入碼帶進安裝程式（手動、映像、Intune／SCCM 派送皆可） | 有加入碼 | 群組總覽看到機器陸續上線 |
| 3. 設定群組 | 選模型、上下文、思考開關、鎖定哪些項目、保留多少記憶體給使用者 | 至少一台上線（才知道有哪些機型） | 看每種機型會拿到哪一版、大概多快 |
| 4. 準備模型 | 按「準備」，各台開始從同群組或內部鏡像取得模型 | 群組設定已存 | 就緒狀態逐台變綠 |
| 5. 套用 | 立即、下次開機或排定時間套用 | 模型就緒（未就緒的機器會等到就緒才套用） | 群組總覽顯示「N／M 台已套用」 |
| 6. 日常 | 看就緒、看誰離線、處理「放不下」與「設定不同」 | 已套用 | 出使用報告 |

**使用者（學生／員工）**

打開桌面安裝的 xConsole 就能用，畫面和個人版相同。受管的項目在設定裡標示「由〇〇管理」，按鈕停用並說明找誰；沒鎖的項目照樣可以改。

**群組頁的設定順序軸**（放在頁面最上方，狀態由真實資料算出）：

1. 加入機器：至少一台在線
2. 設定群組：已存一版群組設定
3. 準備模型：所有在線機器的模型都已就緒，或已標示「放不下，改用 X」
4. 套用：所有在線機器的已套用版本等於最新版
5. 檢查：沒有「設定不同」與「需要重新加入」的機器

## 三、核心功能

### 1. 代理主動連回主控台

**做法**：代理開機後主動以 HTTPS 長輪詢連回主控台。

- `POST /api/agent/poll`：帶節點權杖，主控台最多掛 25 秒，有指令就立即回。
- `POST /api/agent/result`：送回執行結果。

選長輪詢不選 WebSocket，是因為代理只用 Python 標準函式庫，沒有第三方相依。

- **上層程式不動**：`call_node()` 依節點的 `link` 決定走法。`pull` 是現行的主控台連代理，伺服器照舊用這個；`push` 把指令排進那台的佇列，等結果回來，簽名與回傳值都不變。換模型、准入、模型庫這些頁面不必改。
- **驗證**：
  - 代理在加入時取得主控台公鑰並釘住，之後只認這把。沿用現行 `curl --pinnedpubkey` 的做法，不准退回不驗證。
  - 主控台照舊用節點權杖認代理。
- **代理伺服器**：連主控台時要照系統或指定的 HTTPS 代理伺服器走（企業常見）。連本機時繼續不走代理，這是現行的規則。
- **離線不排舊指令**：機器離線期間，主控台不累積指令。關機錯過的變更一律靠群組設定對齊補上，避免隔天開機才執行一個昨天的「停止」。
- **連線上限要改**：`tls.TLSServer` 現在是每個來源最多 64 條連線。企業的工作站走 NAT 或 VPN 時，幾百台看起來是同一個 IP，第 65 台就會被拒。已驗證的代理通道要改成依節點計，只有未登入的請求維持依來源計。
- **規模上限**：主控台是每條連線一個執行緒。200 台長輪詢是 200 條閒置執行緒，沒有問題；500 台以上要改用非同步伺服器，到時再做。
- **對外只開通道**：遠端工作的筆電要從外面連回來時，代理通道和管理網頁要能分開聽不同的埠，對外只開代理通道那一個。

### 2. 群組設定與開機對齊

群組是新的一級物件：`id`、名稱、種類標籤（一般／教室／部門，核心只當顯示用）、設定、版本號（只增不減）、更新時間。

群組設定的欄位：

| 欄位 | 用途 |
|---|---|
| `models` | 要哪些模型。可以寫「自動」，由主控台依每台硬體挑版本，見第 4 點 |
| `profile` | 上下文、並行數、思考開關、取樣參數 |
| `locked` | 哪些項目使用者在本機不能改 |
| `reserve_user_gib` | 保留給使用者其他程式的記憶體 |
| `storage_root` | 模型與身分放哪裡（還原卡要指到不還原的磁碟） |
| `sources` | 模型可以從哪裡取得：同群組、內部鏡像、Hugging Face |
| `allowed_models` | 只准用哪些模型（空的就是不限）。強制點在代理，清單內容可由企業版模組產生 |
| `apply_at` | 立即、下次開機或指定時間 |

對齊流程：

1. 代理連上時送出自己已套用的版本。
2. 主控台有比較新的版本就回傳整份設定。
3. 代理逐步執行：取得模型、准入檢查、換上、鎖定，每一步都回報狀態。
4. 失敗就停在那一步並回報原因，已在跑的服務不動（沿用現行換模型的失敗還原）。

**鎖定的強制點在代理**：被鎖的項目，本機網頁與 API 一律拒絕修改。代理每次對齊時，也會把被改過的鎖定項目拉回群組設定的值。

**套用方式**：學校上課是「全部一起換」，企業推送是「一群一群換」。核心只提供「對這個群組套用」與「並行上限」兩個參數；一群一群換的順序與觀察期由企業版模組排。

### 3. 加入與身分

- **群組加入碼**：可用 N 次、有效 T 分鐘，加入時就放進指定群組。名稱可以用樣板（例 `A{01..20}`），或直接用主機名稱。加入碼只顯示一次，資料庫只存雜湊。
- **靜默安裝**：`install.ps1 -Console <網址> -JoinCode <碼> -DataDrive D:`，Linux 與 macOS 的 `install.sh` 也比照。Intune、SCCM 和映像派送都走這條，加入碼只從參數或標準輸入讀，不寫進環境變數。
- **開機就跑**：受管機器一律裝成開機自動啟動。Windows 用 `SYSTEM` 排程，`install.ps1` 系統管理員模式已有；Linux 用 systemd linger。不能只在使用者登入時才啟動，否則教室裡沒人登入的機器收不到設定。
- **身分與複製偵測**：
  - 代理第一次啟動時產生節點身分，並記下硬體指紋：Windows 的 MachineGuid、Linux 的 `/etc/machine-id`、SMBIOS UUID 與主要網卡 MAC。
  - 啟動時指紋對不上，就表示這是複製出來的映像。這時丟掉舊身分，用加入碼重新加入；加入碼已經失效，就在本機畫面顯示「需要重新加入」。
  - 主控台看到同一個身分從兩組指紋連進來時，兩台都標「疑似複製」並拒絕下指令。
- **還原卡自動接回**：身分存在 `storage_root`（不還原的磁碟）。如果還是遺失，群組有開「依硬體接回」時，同一個 SMBIOS UUID 帶有效的群組加入碼來加入，就接回原來那一格。這個開關預設關閉，因為 2026-10-25 的審查重現過「重新安裝可以搶走已納管機器」，接回必須同時符合：群組有開、硬體相同、加入碼有效。

### 4. 混合機型自動挑版本

- 主控台依每台回報的硬體分類（獨立顯卡 NVIDIA／AMD、`unified_split`、`unified_single`、純 CPU）與記憶體大小，用 `recommend.py` 和准入同一條公式，替每台挑引擎與量化。
- 群組設定頁依機型分類列出：會拿到哪個檔、大概多快（估算，畫面寫明），可依機型覆寫。
- 中國來源的模型在這張表與所有出現模型名稱的地方，一律醒目標示「中國來源」；只標示，不自動排除（清單 #27）。
- 放不下的機器一律給替代方案：改小一級的模型、放硬碟、縮上下文。不能只回「記憶體不夠」，這條沿用「一般人的電腦都要跑得起」。
- **推理引擎預先編好**：Windows CUDA／Vulkan、Linux x64 CUDA、macOS Metal 用官方正式版。官方沒有的平台（Jetson 與 GB10 的 aarch64 CUDA），在群組裡挑一台編一次，產物經核對後放進內部鏡像給同平台的機器。不要讓 20 台各自編譯。

### 5. 模型分發

取得模型的順序：同群組已核對過的機器，然後是內部鏡像，最後才是 Hugging Face（要 `sources` 有允許）。

- **工作站之間互傳**：
  - 走代理的 HTTPS。每次傳送由主控台發一張 60 秒、只能用一次的票證，不用長效權杖，符合機密處理鐵則。
  - 支援續傳，每個檔都核對 sha256。sha256 以 Hugging Face 公布的 LFS 雜湊為準。
- **排程**：主控台排成樹狀，拿到的機器再傳給下一台，每台同時最多送 2 份。

  **估算**（1 GbE、實際約 110 MB/s、20 GB 的模型、20 台）：
  - 全部從同一台拉：約 61 分鐘。
  - 樹狀傳：每一輪約 3 分鐘，5 輪到齊，約 15 分鐘。

  實際數字要在第二期實測後改寫。
- **內部鏡像**：主控台或指定的一台機器先從 Hugging Face 取得，工作站一律從內部拿。適用於企業代理伺服器擋外網、或學校外網頻寬小的情況。
- **限速與時段**：可設上課或上班時段的頻寬上限。
- **筆電**：用電池時不下載、不載入大模型；網路是 Windows 的計費連線時不下載。

### 6. 工作站准入

- 底線加上群組的 `reserve_user_gib`。准入仍算「載下去之後最壞剩多少」，而且是用當下的可用記憶體算，使用者已經開著的程式本來就會算進去。
- **使用者優先**（工作站新增）：模型跑著的時候，如果使用者的程式把可用記憶體壓到底線以下，代理可以先卸載模型並通知使用者，不讓整台卡死。群組可以選「卸載模型」或「不動」，工作站預設卸載。
- Windows、macOS 沿用現行的軟底線。

### 7. 群組總覽

- 每台一張卡，顯示狀態：就緒、準備中（下載 x%）、放不下（建議改用 X）、離線（上次連線時間）、設定不同、需要重新加入、疑似複製。
- 標題列顯示「N／M 台就緒」與下一步。
- 輪詢只換有變的數字，照 `ui-no-flicker` 的做法，不整頁重建。
- 卡片排列方式由群組種類決定。核心提供格狀排列；座位圖由企業版模組的教育包提供。
- **導覽**：只有本機一台時（個人版），畫面完全不變。主控台有群組時，「概覽」換成群組總覽，點進群組就是上面的群組頁。

### 8. 多帳號與角色

- 角色分三種：管理者、維運（可以換模型、重啟、套用群組，不能加機器、不能改帳號）、檢視。每個帳號可以限定只能管哪些群組。老師就是「只管自己那間的維運」。
- 授權檢查放在核心，所有 API 都依目前帳號的角色與群組範圍判斷，物件層一律驗。單一登入、以網域群組對應角色，由企業版模組提供。

### 9. 即時問題回報

xConsole 目前沒有這項，全域規則要求每套交付的系統都要有，而且多工作站情境最需要（學生、員工看到數字怪怪的要能當下回報）。

- 每頁一顆回報鈕，數字旁邊一顆「回報數字有誤」。
- 回報時系統自動帶入機器、群組、頁面與當下狀態。
- 管理者與云碩收件人收得到通知，緊急件逾時會催辦。
- 通知名單或郵件伺服器沒設好，管理頁要顯示警示。

參考實作是 xIR `app/report.py`。

## 四、核心與企業版模組的分工

原則：**會影響安全的強制點一律在公開核心**（代理只有一支，強制邏輯可被審查）；**政策內容、場景流程與管理畫面在閉源模組**。模組不能在代理上執行任何程式碼。

| 功能 | 位置 |
|---|---|
| 代理主動連回、群組設定與對齊、群組加入碼、靜默安裝、複製偵測、還原卡接回 | 核心 |
| 混合機型自動挑版本、預編引擎、工作站互傳、內部鏡像 | 核心 |
| 工作站准入（保留記憶體、使用者優先、電池與計費網路） | 核心 |
| 群組總覽（格狀）、多帳號與角色、即時問題回報、模組載入器 | 核心 |
| 鎖定與 `allowed_models` 的強制 | 核心（代理） |
| 座位圖、課堂流程（課前準備、開始上課並鎖定、下課清除）、排程套用、學生求救、教室與全校報表、上課功耗上限 | 企業版模組：教育包 |
| 單一登入（OIDC／Entra ID、AD）、網域群組對應角色、核准模型清單管理、外部 API 白名單、一群一群推送、資產清冊、遠端停用與清除、部門用量與費用分攤、席次授權、簽章安裝包 | 企業版模組：企業包 |

## 五、擴充合約（核心 API 第 1 版）

### 載入

1. 主控台啟動時找 `<安裝目錄>/enterprise/`，或設定檔指定的路徑（只是路徑，不是機密）。
2. 先讀 `manifest.json`，內含模組版本、`core_api`，以及每個檔的 sha256。
3. 用核心內建的云碩公鑰，以 Ed25519 驗 `manifest.sig`（主控台已相依 `cryptography`）。
4. 逐檔核對 sha256。
5. 檢查目錄與檔案只有系統管理員能寫（Windows 檢查 ACL，Linux 與 macOS 檢查擁有者與權限）。
6. 確認 `core_api` 相容。
7. 全部通過才 import。

任一步失敗都以開源核心啟動（等同沒有企業版），並在「設定」顯示原因與修法，不可默默失效。授權（客戶、席次、到期日、功能）由模組自己驗，核心不碰。

公開核心可以被人改掉驗證步驟，所以簽章的作用是**防止被竄改的模組被載入**。它不是防盜版機制，對客戶與文件都照這樣說明。

### 擴充點

模組的入口是 `register(api)`，`api` 只開放以下幾類：

| 擴充點 | 內容 | 核心負責 |
|---|---|---|
| `api.route(method, pattern, handler, role)` | 只能掛在 `/api/ent/` 底下 | 登入、角色與群組範圍、CSRF、本文大小、統一錯誤處理、稽核 |
| `api.static(dir)` | 前端檔案掛在 `/ent/static/`，頁面以 `XC.registerPage()` 註冊 | CSP `script-src 'self'` 照舊 |
| `api.auth_provider(provider)` | 單一登入，回傳身分與網域群組 | 建立票證、處理登出與逾時 |
| `api.role_mapper(fn)` | 網域群組對應到角色與群組範圍 | 授權判斷 |
| `api.group_fields(schema)` | 群組設定加欄位（只能是資料） | 驗證格式；能強制的只有第三節第 2 點列出的核心欄位 |
| `api.group_layout(name, js)` | 群組總覽的排列方式（例如座位圖） | 資料與更新 |
| `api.apply_plan(fn)` | 決定一次套用哪些群組、間隔多久 | 實際套用與並行上限 |
| `api.on(event, fn)` | 事件：上線、離線、准入擋下、對齊結果、問題回報 | 事件內容先過遮罩 |
| `api.report_section(fn)` | 在使用報告加章節 | 報告產生 |
| `api.store(namespace)` | 模組自己的資料表 | AES-256-GCM 加密輔助、`enc:v1:` 前綴 |
| `api.audit(action, target, ok, detail)` | 寫稽核 | 寫入前遮罩 |

公開 repo 放一個測試用的假模組（以測試金鑰簽章），並加 `test/test_module_contract.py`：核心任何改動只要破壞上面的合約就會失敗。合約有不相容的變更時，`core_api` 加一，並保留舊版一個正式版週期。

## 六、資安

`docs/THREAT_MODEL.md` 要新增四條信任邊界，`SECURITY_PLAN.md` 一併更新：

| 邊界 | 主要威脅 | 控制 |
|---|---|---|
| B5 代理 → 主控台通道 | 假主控台下指令；偷節點權杖冒充；大量連線拖垮 | 釘主控台公鑰；權杖密封存放；已驗證通道依節點計連線數；未驗證依來源計 |
| B6 工作站互傳 | 拿到不該拿的檔案；傳來被竄改的模型 | 60 秒一次性票證、只限該檔；逐檔 sha256；只能讀 `storage_root` 下的模型 |
| B7 模組載入 | 被換掉的模組在主控台執行任意程式碼 | Ed25519 簽章、逐檔 sha256、檔案權限檢查、`core_api` 相容檢查 |
| B8 群組加入 | 撿到加入碼塞進惡意機器；複製機搶身分；重新安裝搶走機器 | 加入碼限次數與時限、只存雜湊；硬體指紋；接回預設關閉並且三項都要符合 |

單一登入的 OAuth 回跳邊界在企業版模組的威脅模型裡寫。交付前兩個 repo 都要跑 `check-compliance.sh --level 中`、`check-https.sh`、`audit-secrets.sh`，有「缺」或「高風險」就不算完成。
