# xConsole 模型主控台安全計畫（SECURITY_PLAN）

> 本文件是 xConsole 所有資安文件的真本。威脅模型、ASVS 檢核表、SSDF 對照表、OWASP Top 10 對照表都從這裡引用等級與範圍。
> 版本：v1.0　日期：2026/10/22　負責人：李偉業（jefflee@cloudinfo.com.tw）

## 1. 系統定級

xConsole 是統一記憶體 AI 機（AMD Ryzen AI 395、Jetson／MIC-743、DGX Spark 系列）的模型主控台，能啟動、停止與更換各機的模型服務。本身不處理業務資料，但它握有讓整台機器停擺的操作權，而且會隨機器一起交付給學校、醫院與政府單位，所以我們以中級規劃。

| 項目 | 內容 |
|---|---|
| 客戶／單位類型 | 隨 AI 機交付的政府機關、公立學校、醫院與企業；資安責任等級依客戶認定 |
| 系統防護等級 | 中 |
| 判定依據 | 資料面：只有管理者帳號、來源 IP 與機器量測值，屬內部資料，最高到一般個資（IP）；服務對象：單一機關內部的管理者；中斷影響：模型服務停擺會讓使用 AI 服務的單位中斷，取最高為中 |
| 採用 ASVS 等級 | L2 |
| 滲透測試 | 每年一次，目前為自測（`test/security/test_security.py`，見證據包） |
| 適用法規 | 資通安全管理法、資通系統防護基準（中級）、個人資料保護法 |

## 2. 資料分類

| 資料類別 | 範例欄位 | 分級 | 儲存位置 | 加密 | 保存期限 | 刪除方式 |
|---|---|---|---|---|---|---|
| 管理者帳號 | 帳號名稱、PBKDF2-SHA256（200,000 輪）加鹽雜湊 | 機密 | `~/.xconsole/fleet.json`（0600） | 只存雜湊，不存明文 | 帳號存續期間 | 重設時覆寫 |
| 登入票證 | 隨機 256 位元票證 | 機密 | SQLite `sessions` 表，只存 SHA-256 雜湊 | 雜湊 | 12 小時，登出、換密碼即刪 | 到期自動刪除 |
| 節點代理權杖（主控台端） | 每台機器一把 Bearer 權杖 | 機密 | `fleet.json` | AES-256-GCM（`enc:v1:`），主金鑰 `~/.xconsole/master.key`（0600） | 機器納管期間 | 解除納管時刪除 |
| 節點代理權杖（節點端） | 同上 | 機密 | 各機 `~/.xconsole/token`（0600） | 檔案權限保護（見威脅模型缺口 G2） | 同上 | 重新部署時更換 |
| TLS 私鑰 | 主控台與各機代理的私鑰 | 機密 | `~/.xconsole/tls/key.pem`、`agent-key.pem`（0600） | 伺服器載入需要明文，以檔案權限保護 | 憑證效期 | 換憑證時保留最近 10 份供還原 |
| 待配對 CSR 私鑰 | 網頁產生 CSR 時的私鑰 | 機密 | `~/.xconsole/tls/csr.json` | AES-256-GCM | 到匯入簽回憑證為止 | 套用後自動清除 |
| 模型 API 金鑰 | 管理者在網頁上產生的金鑰 | 機密 | 各機引擎設定檔（0600） | 引擎讀取需要明文，以檔案權限保護；只在產生當下顯示一次 | 到管理者重新產生或關閉 | 覆寫 |
| 稽核紀錄 | 時間、帳號、來源 IP、動作、目標、結果 | 個資（來源 IP）／內部 | SQLite `audit` 表（0600） | 寫入前經 `store.redact()` 遮罩 | 400 天（防護基準中級要求 6 個月以上） | 每日排程刪除超過期限者 |
| 機器取樣 | 記憶體、GPU、各欄位狀態，每 5 分鐘一筆 | 內部 | SQLite `samples` 表 | 無（不含個資與機密） | 400 天 | 同上 |
| 服務使用報告 | 由取樣與稽核彙整的月報 | 內部 | 產生者本機 `dist-report/` | 無 | 依客戶文件保存規定 | 手動 |

本系統不處理敏感個資（病歷、醫療、基因、健康檢查、犯罪前科），也不把任何資料送到外部服務或境外。

## 4. 信任邊界與安全需求

### 4.1 邊界清單

| # | 邊界 | 兩側 | 控制措施摘要 |
|---|---|---|---|
| B1 | 管理者 ↔ 主控台網頁 | 瀏覽器 ↔ `:9400` | 只有 HTTPS（TLS 1.2+），首次啟動自動暫用自簽、網頁匯入正式憑證；CSP、frame-ancestors none、COOP；伺服器端票證；登入節流；POST 只收 application/json |
| B2 | 主控台 ↔ 節點代理 | `:9400` ↔ 各機 `:9401` | HTTPS，以部署時經 SSH 取回的各機憑證驗證對方，沒有就不連；Bearer 權杖只走標頭；代理只接受登錄檔內的欄位與掃描清單內的模型 |
| B3 | IDE／外部服務 ↔ 模型 API | 使用者電腦 ↔ 各機引擎埠（例 `:8081`） | 管理者可在網頁上開啟 API 金鑰；目前為 http 明文（缺口 G1） |
| B4 | 部署者 ↔ 機器 | 開發機 ↔ SSH | SSH 金鑰；登錄檔只能經 SSH 寫入，沒有 API 可以改 |
| B5 | 主控台 ↔ 本機資料 | 主控台程序 ↔ SQLite、設定檔 | 檔案 0600、目錄 0700；機密加密落地或只存雜湊 |
| B6 | 人 | 管理者、離職者、內部人員 | 稽核全記、換密碼即作廢全部登入、客戶端交接時重設密碼 |

### 4.2 安全需求（對應 ASVS 章）

- 認證：自管單一管理者帳號，PBKDF2-SHA256 200,000 輪；同一來源 15 分鐘錯 5 次即擋，登入一次只驗一個、失敗等一秒（不做全域封鎖，免得任何人都能把管理者鎖在門外）；錯誤訊息不區分帳號與密碼（V6）
- 會話：伺服器端票證、HttpOnly＋Secure＋SameSite=Strict、12 小時到期、登出與換密碼即作廢（V7）
- 授權：所有 `/api/*` 預設拒絕，只有 `/healthz`、`/api/health`、`/api/login` 公開；機器與欄位 id 只能指到登錄檔內的項目（V8）
- 輸入：路徑參數以 `[\w.-]+` 白名單比對；模型名稱、網址、上下文長度逐欄驗證；換模型只接受掃描清單；命令參數一律 `shlex.quote`（V2、V5）
- 輸出：統一錯誤處理，不回堆疊；API 回應 `Cache-Control: no-store`；不回代理權杖與金鑰（V13.3）
- 加密：AES-256-GCM；PBKDF2-SHA256；TLS 1.2+；隨機數一律 `secrets`（V11、V12）
- 日誌：誰／何時／從哪裡／做了什麼／結果；集中遮罩；保存 400 天（V16）
- 檔案：只接受憑證類上傳（PFX／PEM／CER／P7B），6 MB 上限，只放記憶體檢查、不落地到 web 目錄（V15）
- AI：主控台不把使用者內容送進模型；實測只送固定提示；不內建、不上架任何模型（AI-1～5，見威脅模型第 4 節）

### 4.3 不適用項

| ASVS 條 | 理由 |
|---|---|
| V6.4 OAuth／OIDC | 不串接外部身分提供者，沒有認證回跳 |
| V6.3 MFA | 目前未實作，列為缺口 G3；交付政府案前依客戶要求補上或以網段限制替代 |
| V8 多租戶 | 一套主控台只服務一個單位、一位管理者，沒有租戶；物件層授權改以「只能指到登錄檔內的機器與欄位」實作並測試 |
| V15.4 惡意軟體掃描 | 上傳只接受憑證檔，解析後只保留憑證與私鑰物件，不保存原檔 |
| V17 WebRTC | 系統無即時音視訊 |
| 映像簽章（cosign） | 不以容器映像交付，交付物為原始碼與釘版本的 Python 環境；完整性以 git tag 與 SBOM 驗證 |

## 5. 事件應變

| 步驟 | 時限 | 負責 |
|---|---|---|
| 偵測與初判（事件等級 1～4） | 立即 | 資安聯絡人 |
| 通知客戶資安窗口並提供通報所需資訊 | 知悉後 1 小時內（配合機關依資通安全管理法通報） | 資安聯絡人 |
| 遏止：重設管理者密碼（同時作廢全部登入）、重新部署代理權杖、重新產生模型 API 金鑰、必要時停止主控台服務 | 2 小時內 | 開發＋系統負責人 |
| 個資外洩評估與當事人通知（本系統個資只有來源 IP） | 依個資法與機關規定 | 系統負責人＋客戶 |
| 根因分析報告（RCA） | 7 天內 | 開發 |
| 回饋流程（更新威脅模型、加測試、更新 skill 已知坑） | RCA 後 14 天 | 開發 |

## 6. 年度複查

每年 10 月：重跑 CI 六道、更新 SBOM、重審威脅模型、重填 ASVS 與 SSDF 對照、做一次滲透測試（自測或第三方）、更新本文件版本。
